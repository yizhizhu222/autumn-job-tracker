# Autumn Job Tracker · 秋招投递看板

在自己的电脑上管理岗位、简历版本和投递进展。下载代码后，用 Python 启动并在浏览器操作；数据保存在本机文件夹。

## v1.4 公司合并、邮件跟踪与求职项目

- 每家公司一张投递卡，多个岗位放在一起比较。进入卡片选择实际申请岗位，同一家公司网申只显示一个入口。邮箱以纯文本展示，不打开Outlook或自动发送邮件。
- 登记成功提交后，该公司所有岗位退出待投、推荐及项目后的岗位列表。旧投递记录自动适用；拒绝或撤回也继续隐藏。已投记录只跟踪实际申请的岗位，不把其他岗位算作已投。误登记可撤销；确实另投过其他岗位可通过补录保留事实。
- 支持整家公司“不感兴趣”并恢复。公司匹配去除空格、统一字符格式与常见公司法律后缀，支持显式别名，不用模糊匹配合并不同企业。
- 邮件申请登记实际发件邮箱、招聘方邮箱、主题和发送日期。在“已投记录 → 邮件与回执跟踪”查看信息、连接QQ/Gmail并只读检查。授权码只存在本次程序内存，重启后重新连接；不会写入数据文件或进入GitHub。
- 检查收件箱及可识别的垃圾邮件夹，读取登记招聘方地址在投递日期后最近的邮件标题；去重展示，不发送、删除或标记已读，不自动更改招聘进度。部分检查和失败分别标示，不据此声称没有邮件。通知使用其他发件地址时需补充该地址或打开邮箱网页查原文。暂不提供本地OAuth，支持服务商允许的IMAP授权码/应用密码；现有聊天连接不等于本机程序已授权。
- 项目推荐必须有具体来源、相关岗位方向和至少两项相关技能需求，排除只有泛化沟通要求、明显硬门槛或没有新增技能证据的项目。零相关JD不推荐项目，也不按专业硬凑三项。优先级依据公司数量和技能缺口，不编造上岸率。
- 每项包含JD原文依据、要补的能力、步骤、交付物、验收标准及最多三条简历写法。简历模板的【占位内容】必须换成实际结果；未完成不能写成经历。旧项目分析存入 `career-plan-history.json`，保留进度证据。

邮件实现使用验证服务器证书的TLS、IMAP只读选择和BODY.PEEK头部读取。参考 [Python IMAP文档](https://docs.python.org/3/library/imaplib.html) 与 [Google应用密码说明](https://support.google.com/accounts/answer/185833)。

## v1.3 简洁界面与标记同步

界面改为侧栏导航与紧凑岗位卡片。先显示公司、岗位、地点、薪资、匹配度和操作入口，详情与简历按需展开。简历项目计划、历史投递依据也默认折叠。

已投递（含拒绝、撤回）、不感兴趣岗位和被排除的平台统一从待投列表、每日推荐缓存及项目后的岗位推荐中隐藏。同岗位的别名和重复条目只显示一次。已投记录保留在历史页，不感兴趣规则可在对应页恢复。刷新、重启或跨标签页操作后继续生效；不同标签页即时通知同步，其他窗口每15秒同步一次，回到窗口时也刷新。

## v1.2 地域、偏好、自启动和项目路线

- **地域找岗位**：顶部“地域”选择省份和城市，可保留或排除地点未知岗位。保存后筛选当前未投列表，后续每日搜索加入地域关键词。全国招聘保留但具体城市需确认；线上面试与远程工作分开理解。纯本地筛选不联网。
- **不感兴趣**：岗位卡片可移除单个岗位、整个来源平台/网站，或包含某关键词的岗位类型，并记录原因。偏好跨重启生效，每日推荐及项目后的岗位列表也会排除。平台以来源域名识别（常见平台合并子域），不连带屏蔽该公司其他网站上的招聘。原始岗位和已投档案保留，“不感兴趣”页可恢复。
- **开机自启动**：顶部按钮读取真实Windows状态，并提供开关。已有本项目定时任务时只改变登录触发器，保留每日触发器；其他安装使用当前用户登录启动项。登录后后台运行，不自动打开浏览器。非Windows显示暂不支持自动设置；移动安装目录后需重新设置。自启动看板不代表自动安装或下载模型。
- **简历与项目**：填写专业、读取或粘贴简历，得到原文技能证据、当前可尝试岗位、3个优先项目，以及项目完成后可补充技能证据的真实岗位。没有经历可只填专业，专业不被当作已掌握技能。
- 项目方案包括问题、数据来源要求、分周步骤、交付物、验收标准与复现要求。按当前岗位库的JD统计可覆盖岗位和公司，展示原文证据；数量是本地样本，不是全市场统计。硬性学历与经验门槛不会被项目消除。
- 已安装的本地Ollama可补充简历诊断与实施建议。模型不可用仍有基础分析，界面区分两者。计划中的项目不会自动写进简历；登记完成必须填写交付物及验收依据，仍属于本人记录。

偏好保存在数据目录的 `job-preferences.json`，项目诊断保存在 `career-plan.json`，均有写入前备份，不进入公开代码包。切换地域、屏蔽岗位或登记投递后，项目计划中的岗位会即时隐藏；覆盖计数是分析时快照，可重新分析更新。

## v1.1 本地 AI 与每日推荐

首页默认显示“今日推荐”。每天北京时间09:00（可调），在服务运行期间生成一批推荐；关机后当天重新启动会补跑。默认目标10个，优先量子行业及少编程岗位；不足时纳入可尝试、待确认的备选。已投岗位不重复出现；已有未投岗位可以重新排序展示，并明确标记为已有岗位。无法核实的新岗位不会凑数。

- 在“本地 AI 设置”导入简历正文、选择模型并填写求职条件。
- 本机 Ollama + Qwen3 4B 负责匹配分析和简历措辞建议，不需要云端密钥；简历正文只发送到 `127.0.0.1:11434`。
- 公开搜索只发送通用求职关键词。公开搜索受网站限制或网络中断时，展示已有候选并说明更新失败原因。
- 每个岗位显示申请入口、资格未知项、简历建议及操作方式。程序不包含自动填写招聘平台或提交申请。
- “本地 AI 微调简历”最多提出3处替换，保护教育信息、日期与数字，保存前展示原文和改文。可导出保持段落顺序的 TXT 正文；PDF支持最多3处单行原位替换。文字太长、跨行、位置不唯一或完整性校验失败时停止导出。原PDF保留，导出后先预览核对字体与版式。

### 安装本地 AI

从 [Ollama 官方网站](https://ollama.com/download/windows) 安装运行程序，然后执行：

```powershell
ollama pull qwen3:4b
python -m pip install -r requirements-ai.txt
python app.py --open
```

可用项目的 `start-local-ai.ps1 -DownloadModel` 启动本机服务并下载模型；便携程序放 `runtime/`，模型放 `models/`，这两个目录不提交Git。模型下载需要联网，下载完成后匹配与微调可离线运行。API依据 [Ollama 官方文档](https://docs.ollama.com/api/chat)。

每日任务在本地服务运行时执行。关闭浏览器不会停止后台服务；关闭程序或关机会停止任务。推荐生成过程中可继续查看投递记录。

## 功能

- 岗位详情、网页申请入口、匹配理由、短板和简历版本放在同一张卡片。
- 登记真实提交；按北京时间统计今天、近7天、累计数量与每日明细。
- 已投岗位自动从待投清单隐藏；重复登记不重复计数。
- 保留投递时的岗位信息、匹配分析和简历修改快照。
- 满7天仍无实质回复的申请进入复盘列表；自动回执不算实质进展。
- 手动添加岗位，导入/导出岗位库，补录其他渠道的投递，更新进度。
- 每次写入保存最近一份备份；误登记可撤销，撤销记录仍保留。
- 网页按钮只接受HTTP/HTTPS地址；邮件渠道单独列出。

## 运行要求

Python **3.10或以上**和常用浏览器。核心使用Python标准库；PDF正文提取需安装可选的 pypdf 依赖；界面没有CDN资源、外部字体、账号登录或遥测。

### Windows

1. 安装 [Python](https://www.python.org/downloads/)，安装时启用 PATH 或 Python Launcher。
2. 从GitHub选择 **Code → Download ZIP**，解压到任意目录。
3. 双击 `start-windows.cmd`，浏览器会打开 `http://127.0.0.1:18728/`。
4. 保留启动窗口；关闭窗口或按 `Ctrl+C` 停止服务。

也可以运行：

```powershell
python app.py --open
```

### macOS / Linux

```sh
sh start.sh
# 或
python3 app.py --open
```

电脑安装好Python、项目下载完成后，查看/登记/统计/导入导出均可离线使用。打开企业招聘网页仍需要联网。

## 接入已有数据

默认首次启动只创建空白 `data/`，没有真实申请或个人资料。

已有目录包含 `岗位库.json` 和 `投递记录.json` 时，可以直接指定：

```powershell
python app.py --data-dir "E:\面试" --open
```

已有文件不会被初始化覆盖。运行后在页面右上角检查当前数据目录。原有 `原版简历/`、`简历定制/` 相对链接继续有效。使用同一个数据目录时，关闭旧版服务，避免两个程序同时写入。

也可以复制 `config.example.json` 为 `config.json`，设置：

```json
{"data_dir": "E:/面试"}
```

`config.json` 和 `data/` 已加入Git忽略。修改端口使用 `--port 18729`；软件始终只监听本机回环地址。

## 添加岗位与简历

1. 点击“添加岗位”，输入公司、岗位、直达网页、岗位要求和匹配分析。
2. 将简历放进数据目录的 `resumes/` 文件夹，填写相对路径，如 `resumes/resume.pdf`。
3. 页面提供本地预览/下载。简历翻译或修改需提前完成，再填入对应版本。
4. 实际提交成功后点击“我已成功投递，登记”，填写日期、使用的简历与成功依据。

批量导入可参考 `examples/catalog.example.json`。导入只添加新岗位，不覆盖已有条目或投递记录。要更新已有岗位资料，可在关闭服务后编辑岗位库JSON，再重启；不要手工修改稳定的 `key`。

## 一周复盘与自动化范围

应用根据投递日期和进度筛选满7个自然日无实质回复的申请。测评、面试、补材料、拒信、录用等均属于实质进展。该筛选不代表企业拒绝了申请。

本地版已包含公开网页发现、每天推荐、本机模型匹配分析和小幅措辞调整。邮箱连接、系统通知、招聘平台登录与实际提交仍由外部工作流或用户操作。运行程序不会自动发送简历。

## 数据与备份

```text
autumn-job-tracker/
  app.py                   # 本地HTTP服务及数据处理
  web/index.html           # 无外部依赖的前端
  start-windows.cmd
  start.sh
  config.example.json
  examples/                # 仅含虚构示例
  tests/
  tools/
  data/                    # 运行时创建，不提交到Git
    岗位库.json
    投递记录.json
    *.backup.json

```

升级时替换程序文件，保留自己的数据目录及 `config.json`。更换电脑时复制数据目录，或使用导出功能。GitHub仓库用于发布程序源代码；不需要GitHub Pages或云服务器。

## 开发与打包

```sh
python -m unittest discover -s tests -v
python tools/build_release.py
```

发布ZIP位于 `dist/autumn-job-tracker-v1.1.0.zip`。打包脚本使用固定程序文件清单，不会带入运行数据、简历、配置或Git历史。

本项目面向单用户本机使用。服务使用Python标准库HTTP实现；[Python官方文档](https://docs.python.org/3/library/http.server.html)不建议将其作为公网生产服务器。若未来需要多人或公网访问，应另行增加认证、HTTPS和生产级服务部署。
